Problem

Electricity theft hides inside ordinary meter data

A smart meter reports consumption every 15 minutes: 96 readings per day. A tampering consumer manipulates those readings so the bill shrinks while usage does not. Utilities call this non-technical loss.

  • The task, per meter-day: given one query day plus that consumer's preceding reference week, decide original vs manipulated, and if manipulated, identify which of 12 attack mechanisms produced it.
  • Why it is hard: every consumer's normal profile is different, and a skilled manipulation resembles nothing more suspicious than a frugal day.
  • Who pays for errors: a false positive dispatches a site inspection to an honest consumer; the inspection budget, at utility scale, is the binding constraint.

Problem · motivation

The frontier exists, but a utility cannot run on it

A zero-shot proprietary model identifies attacks at 0.929 macro-F1 on this task, ahead of supervised classical baselines. Three properties make that operating point impractical for a utility provider:

  • Metered billing. Every query-day is charged at API rates; the detector's cost scales with the fleet, forever.
  • Data leaves the premises. Consumption traces are personal data; sending them to an external API is a compliance problem, not an engineering one.
  • No adaptation. When a new manipulation pattern appears, a closed model cannot be retrained on it.

The question this work answers

Can small open-weight models (4B to 31B parameters, fine-tuned locally on one GPU) match that frontier, and what does such a detector cost, tolerate, and explain?

Part 1 covers the setup: the data, the input the model reads, and the output it must produce. Part 2 presents the results.

Input · what the model reads

The prompt is the meter data, serialized as text

role + framingYou are a domain expert in smart grid security and electricity theft analysis…
attack catalog · 12 entriesAttack 6: A random cut-off point is selected and all consumption values above it are replaced by that cut-off value… (+11 more)
per-day statistics + calendarDay 1: min=12.40, max=41.20, std=6.10, mean=23.70 Day 1: cal_month=3, dow=0, dom=4 (× 7 reference days + query day)
raw readings · 768 numbersReference week (7 days, 96 readings/day, 15-min intervals): Day 1: 12.40, 11.83, 12.07, 13.51, … Query day (DAY_ID=…): 21.30, 22.14, 24.03, 27.80, 27.80, …
task + output formatDetermine: (1) attacked or original, (2) which attack, (3) its behavior. Return EXACTLY ONE JSON object…

≈7,900 tokens per day, and roughly three-quarters of them are the raw numbers themselves.

  • No feature engineering. Beyond the summary statistics and calendar fields shown, the model receives the raw readings: 96 values × (7 reference days + the query day) = 768 numbers.
  • Text only. No images, no embeddings; the serialized numbers are the entire evidence.
  • Training sees answers, never prompts as targets. Loss is computed on the answer tokens only, so no capacity is spent reproducing the numeric input.
  • Catalog in, or catalog out. The 12 attack descriptions sit in the prompt for classification runs; the explanation study later removes them to force the knowledge into the weights.
Output · what the model must produce

One structured answer: verdict, mechanism, explanation

The fine-tuned workhorse's complete, unedited output for one manipulated evaluation day

{ "classification": "manipulated", "identified_attack": { "most_likely": "attack6", "confidence": "High", "reasoning": "The query day's consumption profile closely follows the normal reference week's shape for most of the day, but exhibits an unnatural flattening during typical peak periods. Specifically, multiple intervals throughout the day are capped at exactly 27.8 Wh, while values below this threshold remain at their normal, variable levels (e.g., 27.7 Wh, 27.0 Wh). This behavior perfectly matches Attack 6, where all readings above a specific cut-off threshold are clipped to that threshold, flattening the peaks and reducing total consumption. This manipulation is typically caused by false data injection. The cut-off threshold parameter is clearly identifiable as 27.8." }, "attack_behavior_explanation": { "manipulation_relative_to_normal": "A cutoff is chosen and every value above it is replaced by that cutoff, flattening the peaks.", "impact_on_magnitude_and_trend": "Changes both trend and amplitude, mostly around the original peaks.", "possible_technical_causes": "False data injection." } }

On a benign day the model outputs "classification": "original" and every other field null. A later variant appends a magnitude block: the estimated fraction of energy removed and the manipulated window. The next slide dissects this same day against its injected ground truth.

  • Verdict, mechanism, evidence, mechanism knowledge. One answer carries the binary decision, the attack identification with stated confidence, the evidence read from the readings, and how that attack behaves in general.
  • From text to metrics. The model outputs text; that text is read back into these fields, and every metric compares the fields to the ground-truth label. The read-back succeeded on 100% of predictions, at every run and training size in the paper.
  • A label alone breaks AUC. Threshold metrics need a probability. With the output held fixed up to the classification field, the model's own probabilities for the two class words are renormalized into p(manipulated), restoring AUC without changing any prediction.
  • Explanations are graded. ROUGE-L against the teacher rationale, and (stricter) whether the stated attack parameter is numerically correct: five attacks have a single recorded value, n = 610 evaluation days.

Within this window, all values are exactly 27.8 Wh, whereas normal historical values for this period typically range between 30.6 and 41.3 Wh.
